# Installed native-conformance.v1 — bounded local controller observation

CLI: `openline-connect conformance --target "python -m openline_connect.conformance_sample"`.
The target is an executable that reads one JSON fixture from stdin and exits with one JSON object on stdout. The fixture includes signed owner permit JWS, a separately signed worker JWS, a local fictional controller loopback URL, pinned owner/controller public keys, supplier-owned SQLite path, plus `recover_only` and `crash_after_commit` controls. It does **not** include the controller private key or an admin credential. The adapter must independently verify owner/worker authority, its policy, bounded job arguments and current context, call `/admit` on the controller itself, and journal the result in its own SQLite.

The controller runs in a separate child process with a separate SQLite journal and Ed25519 signing key. Conformance checks 12 properties: valid native admission, matching signed controller journal, over-cap denial, wrong worker, expiry, epoch revocation with fresh identity, successor exact-receipt recovery, actual subprocess death after journal commit, later `UNKNOWN` recovery without new effect, stale approved context refusal, pre-controller rejection of malformed/expired/revoked attempts, and final journal match. 

Negative control: `python -m openline_connect.conformance_defective` fabricates signed-looking rows and replies without calling controller. This **must exit nonzero**, proving a self-reported outcome is not enough. The harness does not wrap or invoke a supplier effect itself. It never calls the target speculatively for preflight.

This derives the native-admission pattern and falsifier from private PR #121, but is a narrower, newly packaged test profile—not the entire 2026 research suite and not an industry-standard certificate. Same OS user controls both processes in this simulator. A malicious vendor can perform hidden out-of-band effects, tamper with its own logs, or bypass a different real controller. No real ERP delivery, robot actuation, independent operator, or physical safety conclusion is justified. Existing conventional Ed25519 + SQLite systems can implement the same guarantees.
